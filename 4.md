## 1. Core Foundational Concepts

### Collision Domain vs. Broadcast Domain
*This is guaranteed to be asked within the first 60 seconds of your viva.*

| Concept | Collision Domain | Broadcast Domain |
| :--- | :--- | :--- |
| **Definition** | A network segment where data packets can collide with one another when sent simultaneously on a shared medium. | A network segment where an Ethernet broadcast frame (`FF:FF:FF:FF:FF:FF`) sent by one device is received by all other devices in the domain. |
| **Layer** | Physical Layer (Layer 1) | Data Link / Network Layer (Layer 2 / Layer 3) |
| **Hub** | **1 single collision domain** for all connected ports. | **1 single broadcast domain**. |
| **Switch** | **Each switch port is an independent collision domain** (micro-segmentation in full-duplex). | **1 single broadcast domain** across all ports (unless partitioned into VLANs). |
| **Router** | Each router port is an independent collision domain. | **Each router interface breaks and defines a separate broadcast domain** (Routers do NOT forward L2 broadcasts by default). |

> **Viva One-Liner**:  
> *"A switch breaks collision domains per port, but maintains a single broadcast domain. A router breaks both collision domains and broadcast domains per interface."*

---

### CAM Table (MAC Table) vs. Routing Table vs. ARP Table

| Table | Device | Layer | What it Maps | How it is Learned |
| :--- | :--- | :---: | :--- | :--- |
| **MAC Table (CAM Table)** | Switch | L2 | MAC Address $\rightarrow$ Outgoing Switch Port | Dynamically by inspecting the **Source MAC address** of incoming frames. |
| **ARP Table (ARP Cache)** | Host / Router | L2/L3 | IPv4 Address $\rightarrow$ MAC Address | Dynamically via ARP Request (Broadcast) and ARP Reply (Unicast). |
| **Routing Table (FIB/RIB)** | Router / L3 Switch | L3 | Destination Network IP $\rightarrow$ Next-Hop IP / Outgoing Interface | Statically configured or learned via dynamic routing protocols (OSPF, RIP). |

## 2. VLANs & Trunking Deep-Dive

### What is a VLAN?
A **Virtual Local Area Network (VLAN)** is a logical partition of a Layer-2 switch that divides a single physical switch into multiple isolated broadcast domains.
- **Why use VLANs?**
  1. **Security**: Isolates sensitive departments (e.g., Accounts cannot sniff Academic traffic).
  2. **Broadcast Containment**: Prevents broadcast storms from congesting the entire physical network.
  3. **Cost Efficiency**: No need to purchase separate physical switches for each department.

---

### Access Port vs. Trunk Port

```
 Access Port (Fa0/1):                        Trunk Port (Gig0/1):
 Connects to END-HOST (PC/Printer)           Connects SWITCH-TO-SWITCH or SWITCH-TO-ROUTER
 Carries traffic for ONLY 1 VLAN             Carries traffic for MULTIPLE VLANs simultaneously
 Transmits standard UNTAGGED frames          Transmits 802.1Q TAGGED Ethernet frames
```

---

### IEEE 802.1Q Tagging Mechanism
- The standard Ethernet frame does not contain a VLAN field.
- IEEE 802.1Q inserts a **4-byte (32-bit) tag** directly into the Ethernet header between the **Source MAC Address** and the **EtherType / Length** field.
- Structure:
  - **TPID (16 bits)**: Tag Protocol Identifier, always `0x8100`.
  - **TCI (16 bits)**:
    - **PCP (3 bits)**: 802.1p priority for Quality of Service (QoS).
    - **DEI (1 bit)**: Drop Eligible Indicator.
    - **VLAN ID (12 bits)**: Allows $2^{12} = 4096$ IDs (VLAN 1–4094 usable).

---

### What is the Native VLAN?
- By default in IEEE 802.1Q, **VLAN 1** is designated as the **Native VLAN**.
- **Special Property**: Frames belonging to the Native VLAN traversing a trunk link are transmitted **WITHOUT an 802.1Q tag** (plain Ethernet frames).
- **Purpose**: Backward compatibility with legacy switches/devices that do not understand 802.1Q tagging.
- **Viva Warning**: Both ends of a trunk link **MUST match** in Native VLAN configuration; otherwise, switch triggers a "Native VLAN mismatch" CDP error, causing traffic leakage between VLANs!

## 4. Packet Lifecycle: What Changes at Each Hop?

*A classic viva question: "Walk me through what happens when PC-A (192.168.10.10) pings PC-B (192.168.20.10) through Router R1."*

```
[PC-A] (192.168.10.10)                                          [PC-B] (192.168.20.10)
MAC: AA:AA:AA:AA:AA:AA                                          MAC: BB:BB:BB:BB:BB:BB
          |                                                               |
          +---- [Switch] ---- [Router R1] (Gateway) ---- [Switch] --------+
                              g0/0 (LAN 1): MAC RR:11:11:11:11:11 (IP: 192.168.10.1)
                              g0/1 (LAN 2): MAC RR:22:22:22:22:22 (IP: 192.168.20.1)
```

### Step-by-Step Flow:
1. **Subnet Evaluation**:
   - PC-A performs a bitwise `AND` between Destination IP (`192.168.20.10`) and its own Subnet Mask (`255.255.255.0`).
   - PC-A detects PC-B is on a **remote network**.
   - Conclusion: PC-A cannot send directly to PC-B; it must send the packet to its **Default Gateway** (`192.168.10.1`).
2. **ARP for Gateway**:
   - PC-A checks its ARP table for IP `192.168.10.1`. If missing, it broadcasts an **ARP Request**: *"Who has 192.168.10.1? Tell 192.168.10.10."*
   - Router R1 replies with its `g0/0` MAC address (`RR:11:11:11:11:11`).
3. **Hop 1 Frame Creation (PC-A $\rightarrow$ Router R1)**:
   - **Source IP**: `192.168.10.10` (Unchanged!)
   - **Destination IP**: `192.168.20.10` (Unchanged!)
   - **Source MAC**: `AA:AA:AA:AA:AA:AA` (PC-A's MAC)
   - **Destination MAC**: `RR:11:11:11:11:11` (**Router's Gateway MAC!**)
4. **Router Processing**:
   - Router receives frame, checks Frame Check Sequence (FCS), strips Layer-2 Ethernet header.
   - Looks up Destination IP `192.168.20.10` in its **Routing Table**. Finds a match on directly connected interface `g0/1`.
   - Decrements **TTL by 1** (if TTL reaches 0, packet is dropped and ICMP Type 11 sent). Recomputes IP header checksum.
5. **Hop 2 Frame Creation (Router R1 $\rightarrow$ PC-B)**:
   - Router looks up PC-B's IP in its ARP table. If not found, broadcasts ARP on `g0/1`.
   - Router encapsulates the IP packet into a **BRAND NEW Layer-2 Frame**:
   - **Source IP**: `192.168.10.10` (**STAYS SAME!**)
   - **Destination IP**: `192.168.20.10` (**STAYS SAME!**)
   - **Source MAC**: `RR:22:22:22:22:22` (**Router's Outgoing Interface MAC!**)
   - **Destination MAC**: `BB:BB:BB:BB:BB:BB` (**PC-B's MAC!**)

> **The Golden Viva Rule**:  
> **IP addresses remain constant end-to-end; MAC addresses change at EVERY Layer-3 hop!**

## 5. DHCP, ARP & Default Gateway

### The DHCP DORA Process
DHCP operates over **UDP Port 67 (Server)** and **UDP Port 68 (Client)**.

```
 Client (0.0.0.0:68)                              DHCP Server (Port 67)
       |                                                    |
       |  1. DISCOVER (Broadcast: 255.255.255.255)          |
       |--------------------------------------------------->|
       |                                                    |
       |  2. OFFER (Unicast or Broadcast, offers IP)        |
       |<---------------------------------------------------|
       |                                                    |
       |  3. REQUEST (Broadcast: "I choose Server X's IP!") |
       |--------------------------------------------------->|
       |                                                    |
       |  4. ACKNOWLEDGE (Unicast/Broadcast: Lease active)  |
       |<---------------------------------------------------|
```

#### Why is the DHCP REQUEST message broadcast?
If multiple DHCP servers responded with an OFFER, the client chooses one and broadcasts the REQUEST. This broadcast informs the chosen server of acceptance, while politely signaling all other DHCP servers to release their offered IP addresses back into their pools!

---

### What is a DHCP Relay Agent (`ip helper-address`)?
- Routers block Layer-2 broadcast packets (`255.255.255.255`).
- If clients in VLAN 10 need an IP from a central DHCP server in VLAN 50, the router drops the client's `DISCOVER`.
- **Solution**: The command `ip helper-address <DHCP_SERVER_IP>` on the client's gateway subinterface converts the client's broadcast DHCP Discover into a **unicast packet** forwarded directly to the DHCP server!

---

### What is Address Resolution Protocol (ARP)?
- **Purpose**: Maps a known Layer-3 IPv4 address to an unknown Layer-2 48-bit MAC address.
- **ARP Request**: Broadcast (`FF:FF:FF:FF:FF:FF`), Opcode = 1.
- **ARP Reply**: Unicast (direct to requesting host), Opcode = 2.
- **Gratuitous ARP**: An ARP request/reply sent by a host announcing its own IP/MAC to detect duplicate IPs and update neighbors' ARP caches.

## 6. VLSM & Subnetting Viva Math

### Fundamental Formulas:
$$\text{Number of Usable Hosts per Subnet} = 2^h - 2$$
$$\text{Number of Created Subnets} = 2^s$$
*(where $h$ is the number of remaining Host bits, and $s$ is the number of borrowed Subnet bits).*

> **Why subtract 2?**  
> Because the **first address** (all host bits 0) is the **Network ID**, and the **last address** (all host bits 1) is the **Directed Broadcast Address**. Neither can be assigned to a host!

## 7. Spanning Tree Protocol (STP) & Loops

### Why are Switching (Layer-2) Loops Deadlier than Routing (Layer-3) Loops?
1. **No TTL in Ethernet Frames**: Layer-3 IP packets have a Time-to-Live (TTL) field decremented by 1 at each router. If a loop occurs, TTL eventually reaches 0 and the packet is discarded.  
2. **Layer-2 frames have NO TTL field**: An Ethernet frame trapped in a switching loop will loop **infinitely** at line rate until the switch CPU maxes out at 100%, buffers exhaust, and the switch crashes!
3. **Consequences of L2 Loops**:
   - **Broadcast Storms**: Unicast/Broadcast loops multiply exponentially.
   - **MAC Table Instability / Thrashing**: The switch receives the same frame on multiple ports, constantly rewriting its MAC table.
   - **Multiple Frame Copies**: End devices receive identical duplicate packets.

---

### Root Bridge Election & Port Roles
- Switches exchange **BPDUs (Bridge Protocol Data Units)** every 2 seconds.
- Switch with **lowest Bridge ID (Priority + MAC)** becomes Root Bridge.
- **Port Roles**:
  - **Root Port (RP)**: Port on a non-root switch with the lowest root path cost toward the root bridge. (Only 1 RP per non-root switch).
  - **Designated Port (DP)**: Port on a segment that forwards frames toward the root. (All ports on the Root Bridge are DPs!).
  - **Alternate / Blocked Port**: Placed in discarding state to break the loop.

## 8. Port Security & Switch Hardening

### Types of Secure MAC Addresses:
1. **Static**: Manually entered by administrator (`switchport port-security mac-address <MAC>`). Saved in running-config.
2. **Dynamic**: Learned automatically from incoming traffic, stored only in RAM (lost on reboot).
3. **Sticky**: Learned dynamically from connected PC, but **automatically written into the running-config**! (Persists across reboots if config is saved).

---

### Port Security Violation Modes:
- **`shutdown`**: Port immediately transitions to `err-disabled` state, shutting down the link (LED turns red). Generates SNMP trap/syslog. Violation counter increments.
- **`restrict`**: Port drops frames from unauthorized MAC, increments violation counter, and generates SNMP trap/syslog. Port remains operational for authorized MAC.
- **`protect`**: Port drops unauthorized frames quietly. Does NOT increment violation counter; does NOT send alerts.

## 9. Physical Layer & Cabling Standards

```
                     Straight-Through Cable:
  Pin 1: White/Orange  ======================  Pin 1: White/Orange
  Pin 2: Orange        ======================  Pin 2: Orange
  Pin 3: White/Green   ======================  Pin 3: White/Green
  Pin 6: Green         ======================  Pin 6: Green
  (Used between DIFFERENT devices: PC to Switch, Switch to Router)

                     Crossover Cable:
  Pin 1: White/Orange  ----------------------\ /--  Pin 1: White/Green
  Pin 2: Orange        --------------------\  X --  Pin 2: Green
  Pin 3: White/Green   --------------------/  X --  Pin 3: White/Orange
  Pin 6: Green         ----------------------/ \--  Pin 6: Orange
  (Used between SIMILAR devices: Switch to Switch, PC to PC, Router to PC)
```

> **Why does a Router-to-PC connection need a Crossover cable?**  
> Both a PC NIC and a Router physical Ethernet port are **MDI (Medium Dependent Interface)** devices. Their transmit pins are Pins 1 & 2, and receive pins are Pins 3 & 6. Connecting them with a straight-through cable would connect Tx to Tx and Rx to Rx (collision/no signal). A crossover cable connects Tx (1,2) to Rx (3,6)!

## 10. Socket Programming Viva Mastery
*(Directly tested in Week 12 & Week 13 Assignments)*

### System Call Architecture & Deep Defense

#### 1. Why does `accept()` return a NEW file descriptor instead of reusing the listening descriptor?
- **The Listening Socket (`listen_fd`)**: Bound to the well-known port (e.g. 80, 9999) with passive state. Its sole responsibility is to monitor for incoming TCP SYN packets and maintain the pending connection queue.
- **The Connected Socket (`conn_fd`)**: Dedicated exclusively to the active full-duplex session with *that specific client* (identified by the 4-tuple: `Local IP, Local Port, Remote IP, Remote Port`).
- **If `accept()` reused the listening socket**: The server would become deaf to all other incoming client connections while talking to the current client!

#### 2. Why don't UDP sockets use `listen()` or `accept()`?
- UDP is strictly **connectionless** (no 3-way handshake, no virtual circuit, no state machine).
- Datagrams arrive independently. The server uses a single socket descriptor and calls `recvfrom()`, which dynamically reads the source address (`cliaddr`) from the IP/UDP header of each incoming packet.
- There are no separate "connected connections" to queue or accept.

#### 3. What is the role of `backlog` in `listen(int sockfd, int backlog)`?
- It specifies the maximum number of **completed connection requests** (completed 3-way handshake in `ESTABLISHED` state) waiting in the kernel queue to be retrieved by `accept()`.
- **What happens if the queue is full?** The kernel ignores incoming TCP SYNs (or responds with `ECONNREFUSED` / RST), forcing the client to retransmit or fail.

#### 4. How does `fork()` handle socket descriptors in a concurrent server?
- Calling `fork()` creates an exact duplicate child process, which inherits identical copies of all open file descriptors.
- **Child Process Actions**: Calls `close(listen_fd)` (child does not accept new clients; only serves this client) and uses `conn_fd` for communication.
- **Parent Process Actions**: Calls `close(conn_fd)` immediately after fork!
  > **Crucial Viva Point**: Why must the parent close `conn_fd`? Because socket descriptors use **reference counting** in the OS kernel. If parent does not close `conn_fd`, the reference count remains 1 even when the child terminates, preventing the TCP FIN handshake and leaking system resources!

#### 5. Why are `htons()` and `ntohs()` mandatory on x86 architectures?
- Network protocols mandate **Big-Endian** format (Most Significant Byte at lowest memory address).
- Intel x86/x64 processors use **Little-Endian** format (Least Significant Byte first).
- If you assign port 8888 (`0x22B8`) directly without `htons()`:
  $$	ext{x86 memory stores: } 	exttt{0xB8 0x22} \implies 	ext{Network reads: } 	exttt{0xB822} = 47,138!$$
  The server binds to port 47138 instead of 8888, rendering the server completely unreachable!

#### 6. What is `INADDR_ANY`?
- Macro defined as `0.0.0.0`. It instructs the socket to bind to **all active network interfaces** on the host (e.g. Ethernet `192.168.1.5`, Wi-Fi `10.0.0.2`, Loopback `127.0.0.1`).
- If you bound to a specific IP, the socket would only accept packets arriving on that one physical NIC.

## 11. Wireshark, HTTP & Ethernet Frame Deep-Dive
*(Directly tested in Week 0, Week 3, and Week 4 Assignments)*

### 1. Conditional GET & Web Caching
- **Question**: *"Explain how web caching works and why the response payload is 0 bytes."*
- **Defense**:
  - The browser caches a web page along with its `Last-Modified` response header.
  - On the next visit, the client issues an HTTP GET with header: `If-Modified-Since: <cached_timestamp>`.
  - If the server file has not changed, the server sends `HTTP/1.1 304 Not Modified`.
  - **Payload is 0 bytes**: The server does NOT send the HTML body again. The browser serves the file directly from its local disk cache. This eliminates latency and slashes bandwidth usage.

### 2. HTTP 1.0 vs. HTTP 1.1
| Feature | HTTP/1.0 | HTTP/1.1 |
| :--- | :--- | :--- |
| **Connection Model** | Non-persistent by default (1 TCP connection per object) | Persistent by default (`Connection: keep-alive`) |
| **Pipelining** | Not supported | Supported (Multiple requests sent without waiting) |
| **Virtual Hosting** | No `Host:` header | Mandatory `Host:` header (Multiple domains on 1 IP) |
| **Bandwidth Optimization** | Whole resource transferred | Supports Range requests (partial content / byte serving) |

### 3. Why is the Minimum Ethernet Frame 64 Bytes?
- **The CSMA/CD Slot Time**: In half-duplex Ethernet (10BASE5 / 10BASE-T), the maximum network diameter is 2500 meters with 4 repeaters.
- The maximum round-trip propagation delay across the wire is $\sim 51.2\,\mu	ext{s}$.
- At 10 Mbps transmission speed:
  $$	ext{Bits sent in } 51.2\,\mu	ext{s} = 10 	imes 10^6 	ext{ bps} 	imes 51.2 	imes 10^{-6}	ext{ s} = \mathbf{512	ext{ bits}} = \mathbf{64	ext{ Bytes}}$$
- If a frame were smaller than 64 bytes (e.g., 30 bytes), a collision occurring at the far end of the cable would reach the sender *after* it had finished transmitting. The sender would assume the frame was delivered successfully and would never retransmit, causing silent packet loss!
- **Padding**: Any payload smaller than 46 bytes is padded with zeroes to guarantee the 64-byte minimum ($6 + 6 + 2 + 46 + 4 = 64$).

### 4. MAC Address OUI vs NIC Specific
- 48 bits total (6 octets).
- **First 24 bits (3 octets)**: **OUI (Organizationally Unique Identifier)**, assigned by IEEE to the manufacturer (e.g., Cisco, Intel, Realtek).
- **Last 24 bits (3 octets)**: Vendor-assigned serial number.
- **I/G Bit (Bit 0 of 1st Octet)**: `0` = Unicast, `1` = Multicast/Broadcast (`FF:FF:FF:FF:FF:FF` has all bits = 1).
- **U/L Bit (Bit 1 of 1st Octet)**: `0` = Universally administered, `1` = Locally administered.

## 12. IP Header, Fragmentation & ICMP Traceroute Deep-Dive
*(Directly tested in Home Assignment & Wireshark Traces)*

### 1. Why is the Fragment Offset in units of 8 bytes (64 bits)?
- The Total Length field in IPv4 is 16 bits ($2^{16} - 1 = 65,535$ bytes).
- However, the Fragment Offset field is only **13 bits wide** ($2^{13} = 8,192$).
- To address any byte offset up to 65,535 using only 13 bits, the designers scaled the offset by 8 ($8192 	imes 8 = 65,536	ext{ bytes}$).
- **Consequence**: Every fragmented data payload must be a multiple of 8 bytes!

### 2. If an IP packet is fragmented, which fragment contains the TCP/UDP ports?
- **ONLY Fragment 0 (Offset = 0)** contains the L4 transport header (Source Port & Destination Port)!
- Subsequent fragments (Offset > 0) contain raw payload bytes with only the L3 IPv4 header.
- **Security Implication**: Stateless firewalls cannot inspect ports on fragments 1, 2, 3... and must either reassemble packets or block unassociated fragments.

### 3. What happens if a single fragment is lost in transit?
- IP provides unreliable, best-effort service.
- The destination host waits for a reassembly timeout timer (typically 30–60 seconds).
- When the timer expires, the destination **discards all received fragments of that datagram** and sends an ICMP Time Exceeded (Type 11 Code 1: Fragment Reassembly Time Exceeded).
- **IP does not retransmit the missing fragment**; the transport layer (TCP) must retransmit the entire segment!

### 4. How does Traceroute work using ICMP?
- Source sends probe with $	ext{TTL} = 1$.
- Hop 1 router decrements $	ext{TTL} = 0$, discards packet, returns **ICMP Type 11 Code 0 (TTL Expired in Transit)** with its own router IP.
- Source records Hop 1 IP and calculates Round Trip Time (RTT).
- Source repeats with $	ext{TTL} = 2, 3, 4\dots$ until reaching destination.
- Destination replies with **ICMP Echo Reply (Type 0)** or **ICMP Port Unreachable (Type 3 Code 3)**.
- 3 probes per hop are sent to measure latency variance.

## 13. Dynamic Routing (RIP) & CAM Table Aging Deep-Dive
*(Directly tested in Week 5 & Week 9 Assignments)*

### 1. Why is 16 considered infinity in RIP?
- RIP uses Bellman-Ford distance vector routing.
- If a link fails, two adjacent routers can bounce the metric back and forth ($2 	o 3 	o 4 	o 5\dots$), known as the **Count-to-Infinity problem**.
- By setting 16 as Infinity, the loop is guaranteed to terminate in at most 16 iterations rather than running indefinitely.
- **Limitation**: Any network whose diameter exceeds 15 router hops cannot use RIP!

### 2. Split Horizon vs. Poison Reverse
- **Split Horizon**: *"Do not tell your neighbor what you learned from that neighbor."* If Router A learns route to Net 1 from Router B, Router A never advertises Net 1 back to Router B.
- **Poison Reverse**: Rather than suppressing the advertisement, Router A explicitly sends an update for Net 1 back to Router B with **Metric = 16 (Unreachable)**. This immediately purges obsolete route entries from neighbor caches.

### 3. Unknown Unicast Flooding vs. Broadcasting
- **Broadcast Frame**: Addressed to `FF:FF:FF:FF:FF:FF`. Intended for every station on the network (e.g. ARP Request, DHCP Discover). Switch forwards it out of all ports.
- **Unknown Unicast Flooding**: Addressed to a specific unicast MAC address (e.g. `0001.9678.1102`), but the switch does not yet have an entry in its CAM table. The switch temporarily floods it out of all ports in that VLAN. The moment the target replies, the switch learns its port and stops flooding.

## 14. Top 75 High-Probability Viva Questions & Bullet Answers


#### Q1. What is the difference between a Hub, a Switch, and a Router?
- **Hub**: Layer-1 physical device. Repeats incoming bits on all ports. 1 collision domain, 1 broadcast domain.
- **Switch**: Layer-2 device. Forwards frames based on MAC address table. Breaks collision domains per port; 1 single broadcast domain.
- **Router**: Layer-3 device. Forwards packets based on IP routing table. Breaks both collision and broadcast domains per interface.

#### Q2. Why did your very first ping in Packet Tracer say "Request timed out", but subsequent pings succeeded?
- The sender did not have the destination (or default gateway) MAC address in its ARP cache.
- The first packet was queued while an **ARP Request** was broadcast and resolved. The time taken to resolve ARP exceeded the ICMP timeout threshold. Once the ARP cache was populated, all subsequent pings succeeded immediately.

#### Q3. Why can't two hosts in different VLANs communicate without a router?
- Because VLANs operate at Layer 2 and partition the switch into separate, isolated broadcast domains. Layer-2 switches do not rewrite headers or bridge across VLAN boundaries. Moving packets between distinct subnets/VLANs requires Layer-3 routing logic.

#### Q4. What is the function of the `no shutdown` command?
- By default, Cisco router interfaces (and disabled switch ports) are in the `administratively down` state. `no shutdown` toggles the administrative status to `up`, powering on the physical and electrical circuitry of the port.

#### Q5. What is the difference between an SVI and a physical router interface?
- An **SVI (Switched Virtual Interface)** is a logical Layer-3 interface configured on a Multilayer switch (`interface vlan 10`) representing the gateway for that entire VLAN internally without consuming a physical port.
- A **router interface** is a dedicated physical hardware port (`Gig0/0`) requiring external cabling.

#### Q6. What happens if you forget to type `ip routing` on a Cisco 3560 Multilayer Switch?
- The 3560 switch will act purely as a Layer-2 switch. SVIs will be created, but the switch will refuse to route packets between them, and inter-VLAN pings will fail completely.

#### Q7. Why does Router-on-a-Stick require subinterfaces?
- A single physical interface can only have one primary IP address. Subinterfaces allow a single physical port to be logically divided into multiple virtual interfaces, each assigned its own 802.1Q VLAN tag and unique subnet gateway IP.

#### Q8. What is the purpose of the `default-router` command in a Cisco DHCP pool?
- It configures Option 3 of DHCP, instructing client devices which IP address to use as their **Default Gateway** to reach remote networks.

#### Q9. What does the command `switchport trunk encapsulation dot1q` do on a 3560 switch?
- Cisco 3560 switches support both Cisco's proprietary ISL (Inter-Switch Link) and industry-standard IEEE 802.1Q. This command explicitly sets the trunking protocol to 802.1Q before setting the port to trunk mode.

#### Q10. What is the difference between Half-Duplex and Full-Duplex?
- **Half-Duplex**: Data can travel in both directions, but only one direction at a time (e.g., walkie-talkie, shared Hub). Collisions can occur; uses CSMA/CD.
- **Full-Duplex**: Data can transmit and receive simultaneously on separate wire pairs (e.g., telephone, switch port). No collisions; collision detection is disabled.

#### Q11. What is the function of the `ip helper-address` command?
- It configures the router interface to act as a **DHCP Relay Agent**, converting incoming broadcast DHCP Discover/Request messages (`255.255.255.255`) into unicast packets targeted to a remote DHCP server.

#### Q12. What is an `err-disabled` port and how do you recover it?
- A port automatically shut down by Cisco IOS due to a security violation, duplex mismatch, or BPDU guard trigger.  
- **Recovery**: Disconnect the violating device, enter interface configuration mode, type `shutdown`, then type `no shutdown`.

#### Q13. In VLSM, why must subnets with larger host requirements be allocated before smaller ones?
- Allocating larger blocks first prevents fragmentation of the IP address space and ensures that each subnet boundary aligns on natural mathematical power-of-two block sizes.

#### Q14. What is a Default Route and when is it used?
- Configured as `ip route 0.0.0.0 0.0.0.0 <next-hop>`. It is the "gateway of last resort," used to forward packets whose destination IP does not match any specific route in the routing table (e.g., all Internet traffic).

#### Q15. What are the two states of an interface in `show ip interface brief`?
- **Status**: Indicates Layer 1 (Physical/Electrical connectivity, cable connected).
- **Protocol**: Indicates Layer 2 (Data link framing, keepalives, matching clock rate).
- Both must be `up/up` for communication.

#### Q16. What is the difference between Store-and-Forward and Cut-Through switching?
- **Store-and-Forward**: Switch receives the entire frame, verifies the Frame Check Sequence (FCS) CRC for errors, and drops corrupted frames before forwarding. Higher latency, higher reliability.
- **Cut-Through**: Switch reads only the first 6 bytes (Destination MAC) and immediately starts forwarding before the rest of the frame arrives. Lower latency, forwards errors.

#### Q17. How does a switch learn MAC addresses?
- By inspecting the **Source MAC Address** of every incoming Ethernet frame and mapping it to the incoming physical port in its CAM table with an aging timer (default 300 seconds).

#### Q18. What does a switch do if the Destination MAC address is not in its CAM table?
- It performs **Unknown Unicast Flooding**: broadcasts the frame out of every active port within that same VLAN, except the port on which the frame arrived.

#### Q19. What is a Broadcast Storm?
- An endless circulation and multiplication of broadcast frames in a looped Layer-2 topology, consuming all available bandwidth and crashing switch processors.

#### Q20. What is the function of the BPDU in Spanning Tree?
- **Bridge Protocol Data Unit**: Layer-2 control frames exchanged between switches every 2 seconds to elect the Root Bridge, determine root path costs, and block redundant links.

#### Q21. What is the difference between Static MAC, Dynamic MAC, and Sticky MAC?
- **Static**: Manually entered by admin; saved in configuration file.
- **Dynamic**: Learned automatically at runtime; cleared on reboot.
- **Sticky**: Learned dynamically from connected traffic and immediately appended to the switch's running-config.

#### Q22. How many usable hosts can you get from a `/29` subnet?
- $32 - 29 = 3$ host bits.  
- Usable hosts = $2^3 - 2 = 8 - 2 = \mathbf{6\text{ hosts}}$.

#### Q23. What is the Subnet Mask for a `/27` prefix?
- 27 ones: `11111111.11111111.11111111.11100000` = `255.255.255.224`.

#### Q24. Why is a `/30` mask standard for point-to-point router links?
- A `/30` mask provides $2^2 - 2 = \mathbf{2\text{ usable IP addresses}}$ (one for each router interface). It minimizes wastage of IPv4 addresses on dedicated point-to-point links.

#### Q25. What is the difference between Unicast, Broadcast, and Multicast?
- **Unicast**: One sender to one specific destination (`1-to-1`).
- **Broadcast**: One sender to all devices on the local broadcast domain (`1-to-All`, `FF:FF:FF:FF:FF:FF` / `255.255.255.255`).
- **Multicast**: One sender to a specific subscribed group of devices (`1-to-Many`, Class D `224.0.0.0/4`).

#### Q26. What is Auto-MDIX?
- Automatic Medium-Dependent Interface Crossover: A PHY layer hardware feature that automatically detects whether a cable is straight-through or crossover and configures the internal Tx/Rx circuits accordingly.

#### Q27. What is an RJ-45 connector?
- Registered Jack 45: An 8-pin, 8-conductor (8P8C) modular connector used for terminating twisted-pair Ethernet cables.

#### Q28. What is the difference between T568A and T568B?
- The color arrangement of the Green and Orange wire pairs is reversed. T568A has Green on pins 1 & 2; T568B has Orange on pins 1 & 2.

#### Q29. What is a Rollover cable and where is it plugged?
- A cable where pin 1 connects to pin 8, pin 2 to pin 7, etc. It connects a computer's serial/USB port to the RJ-45 **Console Port** of a Cisco device for local out-of-band CLI configuration.

#### Q30. What happens if a frame arrives at an access port with an 802.1Q tag?
- Standard access ports expect untagged frames. If an access port receives a tagged frame, the switch typically drops the frame as invalid.

#### Q31. What is the Native VLAN security risk (VLAN Hopping)?
- If an attacker sends double-tagged 802.1Q frames matching the Native VLAN, the first switch strips the outer Native VLAN tag and forwards the inner tagged frame across the trunk to an unauthorized target VLAN.

#### Q32. What is CIDR?
- **Classless Inter-Domain Routing**: Replaced rigid Class A, B, and C address allocations with arbitrary prefix lengths (e.g., `/26`), allowing flexible subnetting and route summarization.

#### Q33. What is the difference between RIP and OSPF?
- **RIP (Routing Information Protocol)**: Distance-vector protocol, metric is Hop Count (max 15 hops), slow convergence, uses Bellman-Ford.
- **OSPF (Open Shortest Path First)**: Link-state protocol, metric is Cost (based on bandwidth), fast convergence, uses Dijkstra's algorithm.

#### Q34. What is the difference between Administrative Distance and Metric?
- **Administrative Distance (AD)**: Measures the trustworthiness/believability of a routing source (Connected = 0, Static = 1, OSPF = 110, RIP = 120). Lower AD wins.
- **Metric**: Cost used to compare multiple routes learned from the *same* routing protocol.

#### Q35. What does the command `no switchport` do?
- Disables Layer-2 switching features on a physical switch port, converting it into a pure routed Layer-3 port that accepts an IP address.

---


#### Q36. Why does `accept()` return a new socket descriptor in TCP?
- The listening socket must remain open and free to accept incoming connection requests from other clients; the new socket is dedicated to data exchange with this specific client.

#### Q37. What is the difference between TCP stream sockets and UDP datagram sockets?
- TCP (`SOCK_STREAM`) provides reliable, ordered, byte-stream delivery with congestion and flow control. UDP (`SOCK_DGRAM`) provides connectionless, unreliable datagrams of preserved message boundaries without overhead.

#### Q38. What is the purpose of the `backlog` parameter in `listen()`?
- It defines the maximum number of completed, established client connections allowed to queue in kernel memory before calling `accept()`.

#### Q39. What happens if a client attempts to connect to a server whose backlog queue is full?
- The kernel ignores the SYN packet (forcing client retry) or responds with RST / `ECONNREFUSED`.

#### Q40. Why doesn't a UDP client require `bind()`?
- The OS kernel automatically assigns an ephemeral port and binds to the appropriate local interface during the first `sendto()` invocation.

#### Q41. Why must `SO_REUSEADDR` be used on server sockets?
- It allows immediate re-binding to a local port that is lingering in the `TIME_WAIT` TCP teardown state, avoiding "Address already in use" errors upon server restart.

#### Q42. What does `recv()` returning `0` indicate in a TCP socket?
- It signals that the remote peer has performed an orderly shutdown and closed the connection (`EOF`).

#### Q43. What is the function of `inet_pton()`?
- Converts an IPv4/IPv6 address from human presentation string (dotted-decimal) to binary network byte order format.

#### Q44. What is the difference between an iterative server and a concurrent server?
- An iterative server processes one client request to completion before touching the next. A concurrent server forks child processes or spawns threads to serve multiple clients simultaneously.

#### Q45. In a concurrent TCP server using `fork()`, why must the parent process close `conn_fd`?
- To decrement the socket reference count in kernel space so that the connection terminates properly when the child finishes.

#### Q46. What is the function of the `Host` header in HTTP/1.1?
- It allows a single web server with a single IP address to host multiple distinct domain names (Virtual Hosting).

#### Q47. What is an HTTP Conditional GET?
- A GET request carrying `If-Modified-Since` timestamp; the server returns `304 Not Modified` with 0-byte payload if the file hasn't changed.

#### Q48. What is the difference between Persistent HTTP with and without pipelining?
- Without pipelining, the client waits for the response of object $k$ before requesting object $k+1$. With pipelining, requests for all referenced objects are sent back-to-back over the same open TCP connection.

#### Q49. What is the minimum length of an Ethernet II frame and why?
- 64 bytes (excluding preamble/SFD). Required so that CSMA/CD collision detection is guaranteed before the frame transmission finishes.

#### Q50. What is an EtherType field in an Ethernet frame?
- A 2-byte field indicating the encapsulated network-layer protocol (`0x0800` for IPv4, `0x0806` for ARP, `0x86DD` for IPv6).

#### Q51. What is an OUI in a MAC address?
- Organizationally Unique Identifier: the first 24 bits (3 octets) assigned by the IEEE to identify the network hardware manufacturer.

#### Q52. How do you distinguish a Multicast MAC address from a Unicast MAC address?
- If the least significant bit (bit 0) of the first octet is `1`, it is Multicast/Broadcast. If `0`, it is Unicast.

#### Q53. What is Promiscuous Mode in a Network Interface Card?
- A mode that allows the NIC to pass all received Ethernet frames to the operating system, regardless of whether the destination MAC matches the host.

#### Q54. What is the standard Ethernet Maximum Transmission Unit (MTU)?
- 1500 bytes of IP datagram payload (excluding the 14-byte Ethernet header and 4-byte CRC).

#### Q55. In IPv4, why is the Fragment Offset measured in 8-byte units?
- Because the 13-bit offset field must represent offsets up to 65,535 bytes ($2^{13} 	imes 8 = 65,536$).

#### Q56. Which fragment of a fragmented IP datagram contains the TCP or UDP header?
- Only Fragment 0 (Offset = 0).

#### Q57. Where are IP fragments reassembled and why?
- Exclusively at the destination host, because fragments can traverse different router paths to reach the target.

#### Q58. What happens if a single fragment of an IP datagram is lost in transit?
- The destination host discards all received fragments when the reassembly timer expires, and TCP must retransmit the entire segment.

#### Q59. What does an ICMP Type 11 Code 0 message represent?
- Time to Live (TTL) Exceeded in Transit; used by Traceroute to identify intermediate routers.

#### Q60. How does `traceroute` work?
- Sends packets with increasing TTL values (1, 2, 3...); each successive router drops the packet at TTL=0 and returns an ICMP Time Exceeded message revealing its IP address.

#### Q61. What is the maximum hop count allowed in RIP and why?
- 15 hops. Hop 16 represents infinity/unreachable, preventing Count-to-Infinity routing loops.

#### Q62. What is Split Horizon in Distance Vector routing?
- A rule stating that a router must never advertise a route back out of the interface through which it was originally learned.

#### Q63. What is Poison Reverse?
- An explicit rule where a router advertises a failed or learned route back to its source with metric = 16 (unreachable).

#### Q64. What is the difference between RIPv1 and RIPv2?
- RIPv1 is classful, broadcasts updates to `255.255.255.255`, and does not support VLSM. RIPv2 is classless, multicasts to `224.0.0.9`, supports VLSM/CIDR, and includes MD5 authentication.

#### Q65. What is the Administrative Distance of RIP, OSPF, and Static routes?
- Static = 1, OSPF = 110, RIP = 120. Lower AD is preferred.

#### Q66. What is Unknown Unicast Flooding on a switch?
- When a destination MAC is not found in the CAM table, the switch floods the frame out of all ports in the same VLAN except the ingress port.

#### Q67. What is the default CAM table aging time on Cisco switches?
- 300 seconds (5 minutes).

#### Q68. What is the difference between an Access Port and a Trunk Port?
- Access port carries untagged frames for 1 VLAN. Trunk port carries tagged 802.1Q frames for multiple VLANs simultaneously.

#### Q69. What is the Native VLAN in 802.1Q?
- The designated VLAN (default VLAN 1) whose frames traverse the trunk link without an 802.1Q header tag.

#### Q70. What is an SVI on a Multilayer Switch?
- Switched Virtual Interface: a logical Layer-3 interface (`interface vlan X`) that provides inter-VLAN routing without external router hardware.

#### Q71. What command enables routing on a Catalyst 3560 switch?
- `ip routing` in global configuration mode.

#### Q72. Why does Router-on-a-Stick require subinterfaces?
- Because a single physical interface must be partitioned into logical interfaces, each configured with `encapsulation dot1Q <vlan>` and an IP address for that VLAN.

#### Q73. What is the difference between `show ip route` on an MLS vs a Router-on-a-Stick?
- MLS shows routes directly connected to VLAN interfaces (`Vlan10`); ROAS shows routes connected to subinterfaces (`Gig0/0.10`).

#### Q74. What is an `err-disabled` port and how is it restored?
- A port shut down by port security due to a violation. Restored by running `shutdown` followed by `no shutdown` on the interface.

#### Q75. What is the function of DHCP Relay Agent (`ip helper-address`)?
- It converts incoming Layer-2 DHCP broadcast requests (`255.255.255.255`) into Layer-3 unicast packets directed to a remote DHCP server across subnets.


## 15. Professor Trap Questions & Counter-Defenses


*These are the exact trap scenarios professors set during vivas to catch students who just memorized commands.*

### Trap 1: "Can two PCs in different VLANs have the exact same IP address (e.g. 192.168.1.10)?"
- **The Trap**: Most students answer "No, IP addresses must be unique!"
- **The Correct Defense**:  
  *"Yes, at Layer 2 they can! Because each VLAN is an isolated broadcast domain with its own separate ARP and MAC forwarding space. However, they will **NOT** be able to communicate with each other through a router, because the router's routing table cannot have two conflicting routes for the same identical IP/subnet without VRF (Virtual Routing and Forwarding) or NAT."*

---

### Trap 2: "If PC1 and PC2 are connected to the same switch and have IPs in the same subnet (192.168.1.10 and 192.168.1.20), but PC1 is in VLAN 10 and PC2 is in VLAN 20, can they ping each other?"
- **The Trap**: Students think that having the same IP subnet allows them to ping.
- **The Correct Defense**:  
  *"No, they cannot ping! Even though their IP subnets match, the switch isolates their traffic at Layer 2. When PC1 sends an ARP request to resolve PC2's MAC address, the switch drops the broadcast at the boundary of VLAN 10. PC2 never receives the ARP request, so no communication can occur."*

---

### Trap 3: "In Router-on-a-stick, why did you assign IP addresses to `g0/0.10` and `g0/0.20`, but left the physical interface `g0/0` with no IP address?"
- **The Trap**: Professor asks: "Did you forget to give an IP to `g0/0`?"
- **The Correct Defense**:  
  *"No sir, by design! The physical interface `g0/0` carries tagged frames for multiple VLANs over a trunk link. It acts purely as the physical transport carrier. If we assign an IP address directly to `g0/0`, that IP would only belong to untagged native traffic, not to the individual VLANs. Each VLAN needs its own dedicated logical subinterface to act as its specific default gateway."*

---

### Trap 4: "What happens if Switch A has Native VLAN 10 and Switch B has Native VLAN 20 on the trunk link connecting them?"
- **The Trap**: "Does the link just shut down?"
- **The Correct Defense**:  
  *"No, the link stays up, but a **Native VLAN Mismatch** occurs. Cisco Discovery Protocol (CDP) will continuously log error messages. More dangerously, traffic will leak between VLANs! Untagged frames sent by Switch A from VLAN 10 will arrive on Switch B and be treated as belonging to VLAN 20, compromising network segmentation."*

---

### Trap 5: "Why did you run `shutdown` before `no shutdown` to fix an `err-disabled` port?"
- **The Trap**: "Why not just run `no shutdown` directly?"
- **The Correct Defense**:  
  *"Because the `err-disabled` state is an internal software latch. Simply executing `no shutdown` is ignored by the Cisco IOS state machine while the error latch is active. Typing `shutdown` resets the port state machine back to administratively down, clearing the error latch, so that `no shutdown` can successfully re-initialize the interface."*

---

### Trap 6: "If a host doesn't have a Default Gateway configured, can it ever receive an incoming packet from the Internet?"
- **The Trap**: "It has an IP, so can it receive packets?"
- **The Correct Defense**:  
  *"It can technically receive an incoming packet if an outside router forwards it to the host's MAC. However, the host can **never respond or establish a two-way connection**! When the host tries to send an ACK or reply back to the remote IP, it realizes the destination is outside its local subnet. Lacking a default gateway, it drops the return packet immediately!"*


### Trap 7: "If an IP packet is fragmented into 3 parts, does the second fragment have an IP header?"
- **Professor Trap**: Students often say "No, only the payload is fragmented."
- **Counter-Defense**: *"Yes, professor. EVERY fragment gets a complete 20-byte IPv4 header copied from the original datagram, with updated Total Length, Flags (MF=1), and Fragment Offset. Only the transport header (TCP/UDP) is missing from fragments 1 and 2."*

### Trap 8: "Can you run a web server on port 80 and a DNS server on port 80 on the same machine?"
- **Professor Trap**: Seeing if you understand socket tuples.
- **Counter-Defense**: *"Yes, IF one uses TCP port 80 (HTTP) and the other uses UDP port 80 (DNS). The OS kernel socket tuple includes the protocol: `(Protocol, Local IP, Local Port)`. However, two processes cannot bind to `TCP port 80` simultaneously."*

### Trap 9: "In UDP, does `recvfrom()` tell you if the sender crashed?"
- **Professor Trap**: Testing knowledge of connection state.
- **Counter-Defense**: *"No, professor. UDP has zero connection state. `recvfrom()` simply blocks waiting for incoming datagrams. If the sender crashes, the receiver will block forever unless a socket timeout (`SO_RCVTIMEO`) is configured."*

### Trap 10: "If two PCs are in the same VLAN on the same switch, but have IPs in different subnets (e.g. 192.168.1.10/24 and 10.0.0.10/24), can they ping each other without a router?"
- **Professor Trap**: Very common practical trick question.
- **Counter-Defense**: *"No. Even though they share the same Layer-2 broadcast domain, the sending PC performs a bitwise AND with its subnet mask and determines the destination IP is in a remote subnet. It immediately attempts to forward the packet to its Default Gateway. Without a gateway/router, the OS drops the packet before even sending an ARP request!"*

### Trap 11: "Why did you use `htons()` for port numbers, but did not convert array elements in your socket assignment?"
- **Professor Trap**: Testing endianness comprehension.
- **Counter-Defense**: *"Network headers (IP, TCP, UDP ports) are processed by intermediate routers and diverse operating systems across the Internet, requiring standardized Big-Endian order. Application payloads sent between machines of the identical CPU architecture (e.g., both x86-64 Linux) share the same endianness, though for true cross-platform robustness, `htonl()` should be applied to integer payload fields as well."*

### Trap 12: "In RIP, why doesn't a router use the link with the fastest bandwidth instead of lowest hop count?"
- **Professor Trap**: Testing metric comprehension.
- **Counter-Defense**: *"Because RIP's metric is strictly hop count; it is completely blind to link bandwidth, delay, and reliability. A 56 kbps dial-up link with 1 hop will be preferred by RIP over a 10 Gbps fiber link with 2 hops! That is why modern networks use OSPF or EIGRP instead of RIP."*

### Trap 13: "What happens if you connect two switches with an Access link assigned to VLAN 10 on Switch A, and VLAN 20 on Switch B?"
- **Professor Trap**: Testing 802.1Q tagging rules.
- **Counter-Defense**: *"Traffic will leak between VLAN 10 and VLAN 20! Access ports strip tags upon egress. Switch A sends untagged frames from VLAN 10 across the wire; Switch B receives untagged frames on its access port and assigns them to VLAN 20. This creates an unintentional VLAN bridge / security violation."*

### Trap 14: "Why did Wireshark show 0 bytes payload for a 304 Not Modified HTTP response?"
- **Professor Trap**: Testing HTTP caching.
- **Counter-Defense**: *"Because the client already has the identical file in its local cache verified by `If-Modified-Since`. Sending the body again would waste network bandwidth. The 304 status code tells the client to render its locally cached copy."*

### Trap 15: "Why can't a switch port be both an Access port and a Trunk port at the same time?"
- **Professor Trap**: Fundamental L2 concept.
- **Counter-Defense**: *"An access port belongs to exactly one VLAN and sends untagged standard Ethernet frames. A trunk port multiplexes multiple VLANs simultaneously using 4-byte 802.1Q tags. A port cannot simultaneously enforce single-VLAN untagged semantics and multi-VLAN tagged encapsulation."*
