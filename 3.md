# Module 1: Socket Programming

A network socket is defined as an endpoint for communication identified by the tuple:
$$\text{Socket} = (\text{IP Address}, \text{Port Number})$$

### 1. TCP vs. UDP Socket Communication Flow

```
          TCP (Connection-Oriented)                       UDP (Connectionless)
       Server                  Client                  Server               Client
      --------                --------                --------             --------
      socket()                socket()                socket()             socket()
         |                       |                       |                    |
       bind()                    |                     bind()                 |
         |                       |                       |                    |
      listen()                   |                       |                    |
         |                       |                       |                    |
      accept() <--- 3-Way ---- connect()                 |                    |
     (blocks)      Handshake     |                       |                    |
         |                       |                       |                    |
      recv()   <---- Data ----  send()                recvfrom() <--- Data - sendto()
         |                       |                    (blocks)                |
      send()   ---- Data ---->  recv()                 sendto()  --- Data -> recvfrom()
         |                       |                       |                    |
      close()  <--- FIN/ACK --  close()                close()              close()
```

### 2. Core System Calls & Function Signatures

#### A. `socket()` — Create an Endpoint for Communication
```c
int sockfd = socket(int domain, int type, int protocol);
```
- **`domain`**: Communication domain.
  - `AF_INET`: IPv4 Internet protocols.
  - `AF_INET6`: IPv6 Internet protocols.
  - `AF_UNIX` / `AF_LOCAL`: Inter-process communication on the same Unix host.
- **`type`**: Communication semantics.
  - `SOCK_STREAM`: Sequenced, reliable, two-way, connection-based byte streams (**TCP**).
  - `SOCK_DGRAM`: Connectionless, unreliable datagrams of fixed maximum length (**UDP**).
  - `SOCK_RAW`: Direct access to raw network layer (IP/ICMP packets).
- **`protocol`**: Normally `0` (system selects default protocol matching type, i.e., IPPROTO_TCP or IPPROTO_UDP).
- **Return Value**: Socket file descriptor (integer $\ge 0$) on success; `-1` on error.

#### B. `bind()` — Bind Socket to Local Address
```c
int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
```
- Associates socket `sockfd` with a local IP address and port number specified in `addr`.
- **Mandatory for**: TCP servers and UDP servers listening on a well-known port.
- **Optional for**: TCP clients (system automatically assigns an ephemeral port during `connect()`).

#### C. `listen()` — Prepare Socket for Incoming Connections (TCP Server Only)
```c
int listen(int sockfd, int backlog);
```
- Puts socket in **passive mode**, waiting for clients to connect.
- **`backlog`**: The maximum length to which the queue of pending connections may grow. If queue is full, incoming client connections get `ECONNREFUSED`.

#### D. `accept()` — Accept a Connection (TCP Server Only)
```c
int new_sockfd = accept(int sockfd, struct sockaddr *addr, socklen_t *addrlen);
```
- Extracts the first connection request on the queue of pending connections for `sockfd`.
- **CRITICAL EXAM POINT**: `accept()` creates and returns a **NEW connected socket descriptor** (`new_sockfd`) dedicated to communication with that specific client! The original listening socket (`sockfd`) remains open to continue listening for future client connections!

#### E. `connect()` — Connect to Remote Host (TCP Client)
```c
int connect(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
```
- Initiates the **TCP 3-Way Handshake** with the server at `addr`.

#### F. Data Transfer Functions
- **For TCP (Stream)**:
  ```c
  ssize_t send(int sockfd, const void *buf, size_t len, int flags);
  ssize_t recv(int sockfd, void *buf, size_t len, int flags);
  ```
  *(Standard `read()` and `write()` can also be used on TCP socket descriptors).*
- **For UDP (Datagram)**:
  ```c
  ssize_t sendto(int sockfd, const void *buf, size_t len, int flags,
                 const struct sockaddr *dest_addr, socklen_t addrlen);
  ssize_t recvfrom(int sockfd, void *buf, size_t len, int flags,
                   struct sockaddr *src_addr, socklen_t *addrlen);
  ```
  *(UDP preserves message boundaries; each `recvfrom()` corresponds to exactly one `sendto()`)*.

### 3. Key Data Structures & Byte Ordering

#### Data Structures (`<netinet/in.h>`)
```c
struct in_addr {
    in_addr_t s_addr;          // 32-bit IPv4 address (in network byte order)
};

struct sockaddr_in {
    sa_family_t    sin_family; // Address family: AF_INET
    in_port_t      sin_port;   // 16-bit Port number (in network byte order)
    struct in_addr sin_addr;   // IPv4 address
    char           sin_zero[8];// Padding to match size of struct sockaddr (16 bytes total)
};
```

#### Byte Ordering (Endianness)
- **Host Byte Order**: Usually **Little-Endian** on Intel x86/x64 processors (Least Significant Byte stored first).
- **Network Byte Order**: Standardized across the Internet as **Big-Endian** (Most Significant Byte stored first).
- **Conversion Functions**:
  - `htons(val)`: **H**ost **TO** **N**etwork **S**hort (16-bit, used for **Port Numbers**).
  - `htonl(val)`: **H**ost **TO** **N**etwork **L**ong (32-bit, used for **IP Addresses**).
  - `ntohs(val)`: **N**etwork **TO** **H**ost **S**hort (16-bit).
  - `ntohl(val)`: **N**etwork **TO** **H**ost **L**ong (32-bit).

#### IP Address String Conversion
- `inet_addr("192.168.1.10")`: Converts dotted-decimal string to 32-bit binary IPv4 address in network byte order.
- `inet_ntoa(in_addr)`: Converts 32-bit network address to dotted-decimal string.
- `INADDR_ANY`: Macro (`0.0.0.0`) binding socket to **all local network interfaces** on the host.

### 4. Code Logic for MNNIT 2024/2025 Paper Sets

#### Set 1 (2025): Client sends array, Server computes frequency & sum of (element * frequency)
- **Client**:
  ```c
  int arr[] = {3, 1, 2, 2, 3, 3};
  int n = 6;
  send(sockfd, &n, sizeof(int), 0);
  send(sockfd, arr, n * sizeof(int), 0);
  ```
- **Server**:
  - Receives `n`, then receives `arr[n]`.
  - Calculates frequency of distinct elements.
  - Sum of products: $\sum (\text{element} \times \text{frequency})$. Notice: for an array, $\sum (\text{element} \times \text{freq}) \equiv \sum_{i=0}^{n-1} \text{arr}[i]$.
  - Sends back calculated values.

#### Set 2 (2025): Client sends array, Server returns only even numbers in sorted order
- **Server**:
  - Receives array `A`.
  - Filters numbers where `A[i] % 2 == 0`.
  - Sorts them using `qsort()` ascending.
  - Sends filtered array count `k` and the sorted array back to client.

### 2. T568A vs. T568B Wiring Standards (Crucial Quiz Memorization!)

The RJ-45 connector has **8 pins**.

| Pin | T568A Color Scheme | T568B Color Scheme | Function in 10/100Base-T |
| :---: | :--- | :--- | :---: |
| **1** | **White / Green** | **White / Orange** | Transmit + ($Tx+$) |
| **2** | **Green** | **Orange** | Transmit - ($Tx-$) |
| **3** | **White / Orange** | **White / Green** | Receive + ($Rx+$) |
| **4** | Blue | Blue | Unused / Power over Ethernet |
| **5** | White / Blue | White / Blue | Unused / Power over Ethernet |
| **6** | **Orange** | **Green** | Receive - ($Rx-$) |
| **7** | White / Brown | White / Brown | Unused |
| **8** | Brown | Brown | Unused |

> **Key Quiz Rules**:
> 1. In **T568B**, Orange pair is on Pins 1 & 2, Green pair is on Pins 3 & 6.
> 2. In **T568A**, Green pair is on Pins 1 & 2, Orange pair is on Pins 3 & 6.
> 3. Blue (4, 5) and Brown (7, 8) pairs **NEVER change positions** between T568A and T568B!
> 4. In 10/100Base-T Ethernet, only **Pins 1, 2, 3, and 6** are used for data. Gigabit Ethernet (1000Base-T) uses all 8 pins (4 pairs full-duplex).

### 3. Cable Types by Connection

```
                    Straight-Through Cable:
     End 1 (T568B) --------------------------- End 2 (T568B)
     Connects DIFFERENT Layer Devices:
     - PC to Switch / Hub
     - Router to Switch / Hub
     - Server to Switch

                     Crossover Cable:
     End 1 (T568A) --------------------------- End 2 (T568B)
     (Pins 1,2 swap with Pins 3,6!)
     Connects SIMILAR Layer Devices:
     - Switch to Switch
     - Switch to Hub
     - Hub to Hub
     - PC to PC
     - Router to Router
     - Router to PC (Both are MDI hosts!)
```

#### What is Auto-MDIX?
**Automatic Medium-Dependent Interface Crossover**: Modern switch/NIC hardware automatically detects the cable type and electronically switches the internal transmit and receive circuits.

#### What is a Rollover (Console) Cable?
- Pin 1 connects to Pin 8, Pin 2 to Pin 7, Pin 3 to Pin 6, etc. (Completely inverted).
- Used with RJ45-to-DB9 or RJ45-to-USB to connect a PC to a Cisco Router/Switch **Console Port** for out-of-band management.

# Module 3: Wireshark Packet Analysis & Protocol Dissection

### 1. Capture Filters vs. Display Filters

| Feature | Capture Filters (BPF Syntax) | Display Filters (Wireshark Syntax) |
| :--- | :--- | :--- |
| **When Applied** | *Before* capture begins (in libpcap) | *After* capture, while viewing packets |
| **Dropped Packets**| Non-matching packets are discarded forever | All packets kept in memory, only view filtered |
| **Syntax Example** | `host 192.168.1.1 and port 80` | `ip.addr == 192.168.1.1 && tcp.port == 80` |
| **Protocol Only** | `tcp`, `udp`, `icmp`, `arp` | `tcp`, `udp`, `icmp`, `arp`, `dns`, `http`, `dhcp` |

#### Common Wireshark Display Filters for the Quiz:
- `ip.src == 192.168.1.5`: Show packets from source IP.
- `ip.dst == 192.168.1.1`: Show packets to destination IP.
- `tcp.flags.syn == 1 && tcp.flags.ack == 0`: Identifies TCP Connection Request (`SYN` packet).
- `tcp.flags.reset == 1`: Identifies aborted connection (`RST` packet).
- `dns.flags.response == 0`: DNS Query.
- `dns.flags.response == 1`: DNS Response.
- `bootp || dhcp`: Captures DHCP DORA messages.
- `icmp.type == 8`: ICMP Echo Request (Ping).
- `icmp.type == 0`: ICMP Echo Reply (Pong).
- `arp.opcode == 1`: ARP Request.
- `arp.opcode == 2`: ARP Reply.

### 2. TCP 3-Way Handshake Dissection

```
 Client (Port 49152)                             Server (Port 80)
       |                                               |
       |  1. [SYN] Seq = 100, Ack = 0                 |
       |---------------------------------------------->|
       |                                               |
       |  2. [SYN, ACK] Seq = 300, Ack = 101           |
       |<----------------------------------------------|
       |                                               |
       |  3. [ACK] Seq = 101, Ack = 301                |
       |---------------------------------------------->|
       |                                               |
       |  Connection Established! Data Transfer begins |
```

#### TCP Flags Summary (6 Standard Flags):
1. **SYN (Synchronize)**: Synchronizes sequence numbers to initiate a connection.
2. **ACK (Acknowledgment)**: Confirms receipt of bytes; acknowledgment number field is valid.
3. **FIN (Finish)**: Sender has finished transmitting data; initiates connection teardown.
4. **RST (Reset)**: Aborts/resets a connection due to an error, rejected port, or invalid segment.
5. **PSH (Push)**: Tells receiver to push buffered data immediately to the application layer.
6. **URG (Urgent)**: Urgent pointer field is valid; prioritizes urgent data.

#### TCP Connection Teardown (4-Way Handshake):
$$\text{Host A} \xrightarrow{\text{FIN}} \text{Host B}$$
$$\text{Host A} \xleftarrow{\text{ACK}} \text{Host B}$$
$$\text{Host A} \xleftarrow{\text{FIN}} \text{Host B}$$
$$\text{Host A} \xrightarrow{\text{ACK}} \text{Host B}$$

### 3. Protocol Headers Comparison

#### TCP Header (20 to 60 Bytes)
- **Minimum length**: 20 bytes (when Options = 0).
- **Maximum length**: 60 bytes (Options field can be up to 40 bytes).
- **Header Length (HLEN / Data Offset)**: 4 bits, expressed in 32-bit (4-byte) words. Minimum value is $5$ ($5 \times 4 = 20\text{ bytes}$), Maximum value is $15$ ($15 \times 4 = 60\text{ bytes}$).
- **Window Size**: 16 bits (Advertised Receive Window for Flow Control).

#### UDP Header (Fixed 8 Bytes!)
UDP header has **exactly 4 fields**, each of **2 bytes (16 bits)**:
$$\text{UDP Header} = \text{Source Port (16b)} + \text{Dest Port (16b)} + \text{Length (16b)} + \text{Checksum (16b)} = 8\text{ Bytes}$$

# Module 4: DNS (Domain Name System)
*(Syllabus: Lectures 13, 16, 17, Shashank Srivastava Slides & MP 7.1, 7.2)*

### 1. Transport Layer Port
- DNS uses **Port 53**.
- **UDP Port 53**: Used for standard queries and replies because responses are typically small ($< 512\text{ bytes}$) and require low latency without connection handshake overhead.
- **TCP Port 53**: Used when:
  1. Response message size exceeds **512 bytes** (indicated by Truncation bit `TC = 1`).
  2. **Zone Transfers (AXFR/IXFR)** between primary and secondary DNS name servers (requires guaranteed reliability).
  3. DNS over TLS (DoT) uses TCP Port 853.

### 3. Resolution Modes: Iterative vs. Recursive

```
        Recursive Query                                     Iterative Query
   Client ask Local DNS Server:                      Local DNS asks Root DNS:
   "Find IP for www.mnnit.ac.in.                     "What is IP of www.mnnit.ac.in?"
    Do not reply until you have                       Root replies:
    the final IP!"                                   "I don't know, ask .in TLD server."
          |                                                 |
(Local DNS takes full burden)                       Local DNS then asks .in TLD:
                                                     "What is IP of www.mnnit.ac.in?"

```
> **Quiz Rule**: Host-to-Local-DNS query is typically **Recursive**; Local-DNS-to-Remote-DNS queries are typically **Iterative**.

### 4. DNS Resource Records (RR) Format: `(Name, Value, Type, TTL)`

| Record Type | Description / Format | Example |
| :--- | :--- | :--- |
| **A** | Maps Hostname to **IPv4 Address** | `(mnnit.ac.in, 14.139.242.10, A, 86400)` |
| **AAAA** | Maps Hostname to **IPv6 Address** | `(example.com, 2001:db8::1, AAAA, 3600)` |
| **CNAME** | Canonical Name (**Alias** to true hostname) | `(www.mnnit.ac.in, server1.mnnit.ac.in, CNAME, 3600)` |
| **NS** | Authoritative **Name Server** for domain | `(mnnit.ac.in, dns1.mnnit.ac.in, NS, 86400)` |
| **MX** | **Mail Exchange** Server (has a Preference priority) | `(mnnit.ac.in, mail.mnnit.ac.in, MX, 10)` *(Lower preference value = Higher priority!)* |
| **PTR** | Pointer record for **Reverse DNS** (IP to Name) | `(10.242.139.14.in-addr.arpa, mnnit.ac.in, PTR, 86400)` |
| **SOA** | **Start of Authority** (Primary master, admin email, serial, refresh) | Holds zone administration parameters |
| **TXT** | Arbitrary human/machine-readable text | Used for SPF (Sender Policy Framework) and DKIM |

---

### 5. DNS Message Header (Fixed 12 Bytes)
- **ID (16 bits)**: Matches queries to responses.
- **Flags (16 bits)**:
  - **`QR` (1 bit)**: `0` = Query, `1` = Response.
  - **`Opcode` (4 bits)**: `0` = Standard query, `1` = Inverse query, `2` = Server status request.
  - **`AA` (1 bit)**: Authoritative Answer flag.
  - **`TC` (1 bit)**: Truncation flag (set if packet $> 512$ bytes in UDP).
  - **`RD` (1 bit)**: Recursion Desired (set by client).
  - **`RA` (1 bit)**: Recursion Available (set by server).
  - **`RCODE` (4 bits)**: Return Code (`0` = No error, `3` = **NXDOMAIN** / Name Error, `2` = Server Failure).
- **Counts (4 fields $\times$ 16 bits = 8 bytes)**: Question Count, Answer Count, Authority Count, Additional Count.

# Module 5: Cisco IOS Commands, Switching & Routing Fundamentals

### 1. Spanning Tree Protocol (STP — IEEE 802.1D)
- **Purpose**: Prevents Layer-2 loops, broadcast storms, and MAC table instability in redundant switch topologies.
- **Bridge ID (BID)**: $\text{BID} = \text{Bridge Priority (2 bytes)} + \text{MAC Address (6 bytes)}$.
  - Default Priority: `32768`.
- **Root Bridge Election**: Switch with the **LOWEST Bridge ID** becomes the Root Bridge!
- **STP Port Roles**:
  - **Root Port (RP)**: One per non-root switch; port with lowest path cost to Root Bridge.
  - **Designated Port (DP)**: One per network segment; forwards frames. All ports on Root Bridge are DPs!
  - **Blocked / Alternate Port (AP)**: Discards frames to prevent loops.
- **STP Port States & Timers**:
  1. **Blocking**: 20 seconds (Max Age). Receives BPDUs, no frame forwarding.
  2. **Listening**: 15 seconds (Forward Delay). Prepares to forward, no MAC learning.
  3. **Learning**: 15 seconds (Forward Delay). Learns MAC addresses, does not forward data frames.
  4. **Forwarding**: Normal operation; forwards frames and learns MACs.
  *Total Convergence Time* = $20\text{s} + 15\text{s} + 15\text{s} = \mathbf{50\text{ seconds}}$!

---

### 2. IEEE 802.1Q Frame Format
The 802.1Q tag is **4 bytes (32 bits)** inserted between the Source MAC address and EtherType field:
$$\text{802.1Q Tag} = \text{TPID (16 bits)} + \text{TCI (16 bits)}$$
- **TPID (Tag Protocol Identifier)**: Fixed value `0x8100` (identifies frame as 802.1Q tagged).
- **TCI (Tag Control Information)**:
  - **PCP (Priority Code Point)**: 3 bits (QoS Priority levels 0 to 7).
  - **DEI / CFI (Drop Eligible Indicator)**: 1 bit.
  - **VID (VLAN Identifier)**: **12 bits** $\implies 2^{12} = \mathbf{4096\text{ VLAN IDs}}$ (VLAN 0 and 4095 are reserved; usable range is **1 to 4094**).

# Module 6: High-Yield Practice MCQ Question Bank

### Section A: Socket Programming (15 Questions)

**Q1. In a TCP server, which system call returns a new socket descriptor used for actual data communication with the client?**  
A) `socket()`  
B) `bind()`  
C) `listen()`  
D) `accept()`  
**Answer: D**  
*Rationale: `accept()` extracts the pending connection from the queue and creates a new connected socket descriptor; the original listening socket remains open.*

**Q2. Which address family is specified in `socket()` for IPv4 Internet communication?**  
A) `AF_UNIX`  
B) `AF_INET`  
C) `AF_INET6`  
D) `AF_PACKET`  
**Answer: B**  
*Rationale: `AF_INET` stands for Address Family: Internet IPv4.*

**Q3. What does the `backlog` argument in `int listen(int sockfd, int backlog)` specify?**  
A) Maximum number of data packets allowed in the receive buffer  
B) Maximum length of the queue of pending connection requests  
C) Maximum bandwidth in Mbps  
D) Connection timeout in seconds  
**Answer: B**  
*Rationale: Backlog specifies the maximum number of unaccepted client connections the kernel will queue before refusing new ones.*

**Q4. On an Intel x86 computer (Little-Endian), which function must be used to convert a 16-bit port number (e.g., 8080) into Network Byte Order?**  
A) `htonl()`  
B) `ntohl()`  
C) `htons()`  
D) `ntohs()`  
**Answer: C**  
*Rationale: `htons()` converts a 16-bit Short integer from Host to Network byte order.*

**Q5. What is the fundamental difference between `send()`/`recv()` and `sendto()`/`recvfrom()`?**  
A) `send()` is for UDP, `sendto()` is for TCP  
B) `sendto()` and `recvfrom()` accept destination/source socket address pointers required by connectionless UDP  
C) `sendto()` encrypts data  
D) `recvfrom()` cannot block  
**Answer: B**  
*Rationale: UDP is connectionless; every datagram must explicitly state destination/source address via `sendto()`/`recvfrom()`.*

**Q6. Which socket type should be passed to `socket()` to establish a UDP socket?**  
A) `SOCK_STREAM`  
B) `SOCK_DGRAM`  
C) `SOCK_RAW`  
D) `SOCK_SEQPACKET`  
**Answer: B**  
*Rationale: `SOCK_DGRAM` creates an unreliable, connectionless datagram socket (UDP).*

**Q7. What happens if a client attempts to execute `connect()` on a port where no server is listening?**  
A) The client blocks forever  
B) The server host OS returns a TCP segment with the `RST` (Reset) flag set, raising `ECONNREFUSED`  
C) The client automatically starts a server  
D) The DNS server handles the request  
**Answer: B**  
*Rationale: A host receiving a TCP segment for an unopened port replies with a TCP Reset (`RST`).*

**Q8. What does `INADDR_ANY` represent when configuring a server socket address?**  
A) Any client is rejected  
B) Socket binds to all available network interfaces (`0.0.0.0`) on the local machine  
C) Server IP is dynamically assigned by DHCP  
D) Broadcast address `255.255.255.255`  
**Answer: B**  
*Rationale: `INADDR_ANY` binds the socket to listen on all local network interface IP addresses.*

**Q9. Which field in `struct sockaddr_in` stores the port number?**  
A) `sin_family`  
B) `sin_port`  
C) `sin_addr`  
D) `sin_zero`  
**Answer: B**  
*Rationale: `sin_port` is an `in_port_t` (16-bit integer) holding the port in network byte order.*

**Q10. Can a client call `sendto()` on a UDP socket without explicitly calling `bind()` first?**  
A) No, `bind()` is strictly mandatory  
B) Yes, the kernel automatically binds the socket to an ephemeral port and local IP on the first `sendto()`  
C) Yes, but the packet will have no source port  
D) No, the OS will throw a segmentation fault  
**Answer: B**  
*Rationale: If an unbound socket transmits data, the OS automatically assigns an unused ephemeral port.*

**Q11. What is the return value of `recv()` when the peer has performed an orderly shutdown (`close()`) of the TCP connection?**  
A) `-1`  
B) `0`  
C) `1`  
D) `EOF` constant  
**Answer: B**  
*Rationale: In TCP, `recv()` returning `0` indicates End-of-File (peer closed connection gracefully).*

**Q15. Why is TCP referred to as a "byte-stream" protocol while UDP is "datagram-oriented"?**

**Q28. What is the fixed size of a UDP header?**
